# Voice-first optional onboarding: production pilot

**Owner:** Group PM execution via Codex. **Status:** implementation in review; production allocation OFF. No deployment from unreconciled main or PR #4.

**Problem / hypothesis.** New users may leave optional profile setup before reaching value. Presenting voice first, while preserving typing and skips, may increase useful first Meera interactions. Change only the initially presented mode: control = typed-first; treatment = voice-first. Keep questions, order, copy, voices, languages, save behavior, prices and entitlements identical. Neither arm requests microphone permission without a user gesture. Switching mode is allowed and measured; analyze by assigned arm.

**Eligibility / assignment / exposure.** Verified Google accounts created after activation and less than 24 hours old, first entering the explicit `/onboarding` URL, with an incomplete profile. Exclude internal/company identities, explicit QA accounts, completed profiles and pre-existing accounts. Server-owned deterministic 50/50 assignment persists across sessions/devices. Initially enroll at most 10% of eligible entries, capped at 40 distinct accounts. Exposure is recorded only after the assigned mode is visibly rendered, once per assignment. Report assignment and exposure counts separately; use assigned users for the primary denominator.

**Outcome / instrumentation.** Primary: fraction of assigned users who confirm “This helped” on a completed, non-onboarding Meera response within 24 hours of assignment (self-reported usefulness, not a model-inferred label). Secondary: signup-to-profile-save completion and time, Start-to-save time, response delay, switch/fallback rate and onward arrival. Save is recorded server-side after a committed profile write; reload verifies persistence. First useful response confirmation appears identically for both arms after an actual completed workspace answer. Report unpaid checkout arrival, successful payment and QA separately; onboarding never grants a subscription. Event payloads accept only enums, booleans and bounded durations—no profile values, transcripts or recordings. Only aggregate counts/rates/timing summaries go to Week 7.

**Decision rule.** Run until 40 assignments or 72 hours, whichever comes first; close enrollment and wait 24 hours for outcomes. Minimum 15 matured users per arm; otherwise report insufficient evidence and iterate the pilot. A ≥10 percentage-point primary uplift with no >5-point completion decrease and no guardrail failures supports retaining voice-first for another limited pilot. Smaller differences or substantial mode switching → iterate; worse outcomes or guardrail failures → revert the entry mode. These are directional learning rules, not statistical proof or a global-launch decision. Report counts, intervals and missing-event coverage; do not compare immature cohorts.

**Stop conditions.** Immediate disable for privacy/account-isolation failures, lost drafts, broken typing fallback or entitlement/checkout regressions. Pause for ≥2 confirmed provider 429s, >5% provider failures after 20 answers, or p95 response delay >8 seconds after 10 measured responses. Review aggregate guards after every five pilot users; the control report recommends pausing on threshold breaches. Check remaining OpenRouter allowance before activation and daily; pause below $2 or on unknown budget status. Retain the $9.90 lifetime cap and no reset; never copy the production key into staging. Close enrollment no later than 18 November 2026, 4 PM IST; key expiry is 19 November about 5:13 PM IST. These dates are operational limits, not evidence that activation occurred.

**Release / acceptance / rollback.** Recover and hash-verify every production source path, version the release baseline, reconcile extra runtime paths, build without production secrets in staging and verify the exact team/project/commit before release. Acceptance requires real desktop Chrome, Android Chrome and iPhone Safari: both voices × English/Hindi/Hinglish; speech, correction, optional skips, save/reload, denied mic → typing, two-account isolation, mic release, completed-profile onward journey and unpaid checkout. Automated devices/audio are explicitly synthetic. Test the per-experiment off switch and rollback in isolation; production rollback remains the known-good deployment above. Activation requires recorded evidence for all gates and named reporting/operator access. Ship instrumentation dark first only after baseline reconciliation; start the small pilot only after acceptance. Recommend HOLD until those gates are proven, then measure and decide from production aggregates.
